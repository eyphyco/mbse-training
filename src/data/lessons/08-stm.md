## 状態機械図は何を表す図か {#stm-purpose}
items: mu-stm-purpose
term: 状態機械図 | じょうたいきかいず | stm。ブロックがイベントに応じてどの状態からどの状態へ移るかを表す図
term: 状態 | じょうたい | ある条件が成り立っている間。角の丸い長方形で描く

### 一文で

**stm は、イベントが来たときに状態がどう変わるかを表す図**。ブロック 1 つの**ライフサイクル**を描く。

### いつ使うか

- **モード**がある（停止中・走行中・故障中）
- 同じイベントでも、**今の状態によって反応が違う**

### 利点

- 起こりうる状態と移り方を**漏れなく**並べられる
- 「この状態でこのイベントが来たら？」を図で確かめられる

## 状態と領域・初期と終了 {#stm-state}
items: mu-state-region
figures: stm-regions
term: 初期状態 | しょきじょうたい | 黒丸 ●。状態機械（または領域）が始まったとき最初に入る状態を指す擬似状態
term: 終了状態 | しゅうりょうじょうたい | 二重丸 ◉。そこに着くとその領域が終わる
term: 領域 | りょういき | region。状態の中を破線で区切った部分。それぞれが同時に（並行に）動く

### 記号

| 記号 | 名前 | 意味 |
| --- | --- | --- |
| 角丸の長方形 | 状態 | 条件が成り立っている間 |
| 黒丸 ● | 初期（擬似状態） | 最初の状態を指す。**とどまらない** |
| 二重丸 ◉ | 終了状態 | その領域が終わる |
| 状態の中の状態 | 複合状態 | 入れ子 |
| 状態の中の**破線**の区切り | **領域** | 各領域が**同時に**動く |
| ひし形 | 選択 | ガードで行き先を選ぶ |
| H の丸 | 履歴 | 前回抜けた所へ戻る |

### ここが最重要: 領域は並行

複合状態を**破線で区切った**ら、それぞれの領域は**同時に**状態を持つ。
「走行中」の中に「変速」と「空調」の領域があれば、2 つの状態を**同時に**持っている。

### 初期は状態ではない

黒丸は**擬似状態**で、とどまれない。始まったらすぐ、矢印の先の状態に入る。

## entry / do / exit {#stm-behavior}
items: mu-state-behavior
term: entry | えんとりー | 状態に入るときに 1 回行う振る舞い
term: do | どぅー | 状態にいる間ずっと行う振る舞い。終わると完了遷移が起きうる
term: exit | えぐじっと | 状態を出るときに 1 回行う振る舞い

### 状態の中の振る舞い

```
┌─────────────────────┐
│ Running             │
│ entry / startMotor  │
│ do / monitorSpeed   │
│ exit / stopMotor    │
└─────────────────────┘
```

| 欄 | いつ |
| --- | --- |
| `entry /` | **入るとき 1 回** |
| `do /` | **いる間ずっと**（遷移が起きたら中断される） |
| `exit /` | **出るとき 1 回** |

## 遷移 {#stm-transition}
items: mu-transition
figures: stm-engine
term: 遷移 | せんい | 状態から状態への矢印。`トリガ [ガード] / 効果` の形でラベルを付ける

### ラベルの 3 つの欄

```
トリガ [ガード] / 効果
brake [speed > 0] / applyBrakes
```

| 欄 | 意味 | 無いとき |
| --- | --- | --- |
| トリガ | どのイベントで | **完了遷移**（状態の do が終わったら） |
| `[ガード]` | 条件が真なら | 常に真 |
| `/ 効果` | 遷移するときに行うこと | 何もしない |

### トリガの種類

| 書き方 | 種類 |
| --- | --- |
| `start` | シグナルイベント（シグナルが届いた） |
| `after(5 s)` | 時間イベント（入ってから 5 秒） |
| `at(12:00)` | 時間イベント（時刻） |
| `when(temp > 90)` | 変化イベント（条件が真になった瞬間） |

### 読み方の手順

1. イベントが来たら、**今の状態から出る遷移**のうち、トリガが合うものを探す
2. ガードが**真のもの**だけが候補
3. 遷移する: **元の状態の exit → 効果 → 先の状態の entry** の順（前の節）

### 順番の問題

A から B へ、効果 e で遷移するときの順は:

**A の exit → e → B の entry → B の do**

試験はこの順番を並べ替えさせる形でよく出る。自分自身へ戻る遷移（外部遷移）でも、**exit と entry は実行される**。

### 取り違えやすい点

- **ガードとトリガ**: `[speed > 0]` は条件で、それ自体はイベントではない。`when(speed > 0)` はイベント
- **after の起点**: その状態に**入った時**から数える

## 状態機械図を作る {#stm-build}
items: mbf-build-stm

### 手順

1. **ヘッダ**: `stm [stateMachine] 名前 [図の名前]`
2. **初期**（●）から最初の状態へ矢印
3. 状態を並べ、`entry / do / exit` を書く
4. 遷移に `トリガ [ガード] / 効果` を書く
5. 同時に動く側面は**領域**に分ける（破線）
6. 終わるなら終了状態（◉）

### 確かめる観点

| 観点 | 正しい形 |
| --- | --- |
| ヘッダの型 | `stateMachine` |
| 初期 | 各領域に 1 つ |
| 同じトリガの遷移が複数 | ガードが重ならない |
| 時間 | `after(…)` はトリガ欄に |
| 並行 | 破線の領域 |
