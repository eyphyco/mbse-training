## ibd は何を表す図か {#ibd-purpose}
items: mu-ibd-purpose
term: 内部ブロック図 | ないぶぶろっくず | ibd。1 つのブロックの内部で、パートどうしがどうつながるかを表す図
term: 囲みブロック | かこみぶろっく | ibd が中身を描いている対象のブロック。図枠そのものが囲みブロックを表す
term: コネクタ | こねくた | ibd のパート（またはポート）どうしをつなぐ実線。つながっていることだけを表す

### 一文で

**ibd は 1 つのブロック（囲みブロック）の内部を描き、パートどうしの接続を表す図**。

```
ibd [block] Vehicle [Powertrain]
┌──────────────────────────────────────┐
│  ┌──────────────┐    ┌─────────────┐ │
│  │ engine:Engine│────│ trans:Trans │ │
│  └──────────────┘    └─────────────┘ │
└──────────────────────────────────────┘
```

- **図枠が囲みブロック**（ヘッダの②は必ず `block`）
- 中の箱は**パート**（`名前 : 型`）。ブロックそのものではない
- 線は**コネクタ**（接続）

### bdd との関係

| | bdd | ibd |
| --- | --- | --- |
| 箱 | ブロック（型） | パート（使用） |
| 箱の文字 | `«block» Engine` | `engine : Engine` |
| 線 | 持つ・一種 | **つながる** |

**ibd に出るパートは、bdd の parts 区画（＝黒ひし形）と一致していなければならない**。bdd に無いパートが ibd に突然出てきたら誤り。

### 利点

- 同じ型のパートが 2 つあっても、**どちらがどこにつながるか**を区別できる（bdd ではできない）
- 出入口と、そこを流れるものを明示できる（この章の後半）

## パートの表し方 {#ibd-parts}
items: mu-part-repr
term: 参照パート | さんしょうぱーと | ibd で破線の箱で描く、参照プロパティ。囲みブロックが持たずに指している相手

### 箱の種類

| 箱 | 意味 |
| --- | --- |
| 実線の箱 `engine : Engine` | パート（持ち物） |
| **破線**の箱 `driver : Driver` | **参照**（持たずに指す） |
| 箱の右上の `4` や `[4]` | 多重度 |
| 箱の中にさらに箱 | 入れ子のパート（パートのパート） |

### 名前の書き方

| 書き方 | 意味 |
| --- | --- |
| `engine : Engine` | 名前と型 |
| `: Engine` | 型だけ（名前を省略） |
| `engine` | 名前だけ（型を省略） |
| `powertrain.engine : Engine` | **ドット記法**。入れ子のパートを外から指す |

### 試験での問われ方

- 「破線の箱は何か」→ 参照。囲みブロックが消えても残る
- 「`: Engine` はブロックか」→ 名前を省略したパート。ibd の箱は常に使用

## ポート {#ibd-ports}
items: mu-ports
figures: bdd-ports
term: ポート | ぽーと | ブロックの境界にある出入口。小さな四角で描く。v1.2 ではフローポートと標準ポートの 2 種
term: フローポート | ふろーぽーと | 物・エネルギー・データの流れの出入口。四角の中の矢印が向き（入る・出る・両方向）
term: 標準ポート | ひょうじゅんぽーと | サービス（操作）の出入口。矢印の無い四角。提供・要求インタフェースを持つ
term: フロー仕様 | ふろーしよう | «flowSpecification»。複数の流れを束ねたフローポートの型。向き付きのフロー属性を持つ

### v1.2 のポートは 2 種類

| ポート | 四角の中 | 何が出入りするか | 型 |
| --- | --- | --- | --- |
| **フローポート** | 矢印（→ ← ↔） | 物・エネルギー・データの**流れ** | ブロック・値型・シグナル・フロー仕様 |
| **標準ポート** | 何も無い | サービス（**操作の呼び出し**） | インタフェースを提供・要求 |

> フル／プロキシポートは **v1.3 から**。v1.2 の試験には出ない。v1.3 以降の資料で見たら、混乱しないよう脇に置く。

### フローポートの向き

| 矢印 | 向き | 意味 |
| --- | --- | --- |
| ブロックの内側へ | `in` | 入る |
| ブロックの外側へ | `out` | 出る |
| 両向き | `inout` | 両方 |

1 種類だけ流れるフローポート（**アトミック**）は、流れるものの型で型付けする（`fuelIn : Fuel`）。
複数が束で流れるなら（**非アトミック**）、`«flowSpecification»` で束ね、それで型付けする。

### 共役（~）

`line : ~FuelLine` のように型の前に `~` が付くと**共役**。フロー仕様の in と out を**入れ替えて**使う。
送る側と受ける側で同じフロー仕様を使い、片方を共役にすると向きが噛み合う。

### 標準ポートのインタフェース

- **提供インタフェース**: ポートから伸びた**丸**（ボール）。この操作を受け付ける
- **要求インタフェース**: ポートから伸びた**半円**（ソケット）。この操作を呼ぶ

## コネクタと項目フロー {#ibd-connectors}
items: mu-connector-itemflow
term: 項目フロー | こうもくふろー | コネクタの上の黒い三角と名前。そのコネクタを実際に何がどちら向きに流れるかを表す

### コネクタ

- パートとパート、ポートとポートを**実線**でつなぐ
- 意味は「**つながっている**」だけ。何が流れるかは言わない
- 名前と型を付けられる（`c1 : FuelPipe`）。型は bdd の関連

### 項目フロー

コネクタの上に**黒い三角**と名前を置くと、**何がどちらへ流れるか**を表す。

```
tank:FuelTank ─────▶──── engine:Engine
                  fuel : Fuel
```

| 要素 | 意味 |
| --- | --- |
| 黒い三角の向き | 流れる向き |
| `fuel` | 項目プロパティ（流れの名前） |
| `Fuel` | 流れるものの型（項目の型） |

### 見分けの要点

- コネクタは**構造**（つながりがある）、項目フローは**流れ**（何が流れる）
- フローポートの向きと項目フローの向きは**噛み合っていなければならない**（out から in へ）
- 項目フローの型は、両端のポートが**受け付けられる**型であること

## ibd を作る {#ibd-build}
items: mbf-build-ibd

### 手順

1. **ヘッダ**: `ibd [block] 囲みブロック [図の名前]`
2. bdd の parts 区画（黒ひし形の先）から**パートを並べる**。名前と型を bdd に合わせる
3. 参照があれば**破線の箱**で置く
4. 境界の出入口を**ポート**で置く。流れならフローポート（向き）、サービスなら標準ポート
5. **コネクタ**でつなぐ。囲みブロックの外とつながる所は、**図枠の上のポート**へ引く
6. 流れるものを**項目フロー**で示す

### 確かめる観点

| 観点 | 正しい形 |
| --- | --- |
| ヘッダの型 | 必ず `block` |
| パート | bdd のコンポジションと一致（名前・型・多重度） |
| 参照 | 破線の箱 |
| フローポートの向き | out → in に流れる。inout はどちらでも |
| 項目フロー | 矢印の向きがポートの向きと噛み合う |
| 図枠のポート | 囲みブロック自身のポート |
