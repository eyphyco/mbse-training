## パッケージ図は何を表す図か {#pkg-purpose}
items: mu-pkg-purpose
term: パッケージ | ぱっけーじ | モデル要素を入れる入れ物。左上に札の付いたフォルダの形で描く
term: パッケージ図 | ぱっけーじず | pkg。パッケージの入れ子と、パッケージ間の依存を表す図

### 一文で

**pkg はモデルの整理棚を表す図**。どのパッケージに何が入り、パッケージどうしがどう依存するかを描く。

| 記号 | 意味 |
| --- | --- |
| フォルダの形 | パッケージ |
| フォルダの中の記号 | そのパッケージが持つ要素 |
| ○に＋の付いた線 | **包含**（持ち主の側に ⊕） |
| 破線の矢印 | 依存（`«import»` など） |

### 利点

- 大きなモデルを**分担・管理**できる単位に分ける
- 名前の衝突を避ける（パッケージごとに名前の範囲が分かれる）
- 何度も使う部品集（値型・単位など）を切り出して共有できる

## 所有と名前空間 {#pkg-ownership}
items: mu-pkg-ownership
term: 名前空間 | なまえくうかん | 名前が一意である範囲。パッケージは名前空間で、中の要素は `Package::Element` の形の完全修飾名で指せる
term: 所有 | しょゆう | 要素がちょうど 1 つの持ち主（パッケージなど）に属すること。持ち主が消えると要素も消える

### ここが最重要: 持ち主は 1 つ

**モデルの要素は、ちょうど 1 つの持ち主に属する**。同じ要素が 2 つのパッケージに入ることはない。
（図に何度出てもよい。図はモデルの見え方にすぎない — 章 0）

### 完全修飾名

パッケージは名前空間なので、別のパッケージに同じ名前があってもよい。区別するときは `::` でつなぐ。

```
Structure::Vehicle
Analysis::Vehicle      ← 別の要素
```

### 包含の描き方

| 描き方 | 意味 |
| --- | --- |
| フォルダの中に要素を描く | 包含 |
| 持ち主の側に ⊕ の付いた線 | 包含（同じ意味。図が混むときに使う） |

⊕ は**持ち主の側**に付く。ひし形と同じく、向きを取り違えない。

## 包含と依存 {#pkg-relations}
items: mu-pkg-relations
term: 依存 | いぞん | dependency。破線の開いた矢印。矢印の元が先の要素に依存している（先が変わると元に影響する）
term: インポート | いんぽーと | «import»。別のパッケージの要素を、完全修飾名なしで使えるようにする依存

### 依存の種類

| 表記 | 意味 |
| --- | --- |
| 破線の矢印（名前なし） | 依存。先が変わると元が影響を受ける |
| `«import»` | 公開インポート。取り込んだ名前を、さらに外にも見せる |
| `«access»` | 非公開インポート。取り込んだ名前を自分の中だけで使う |

### 向き

**矢印の元が依存する側**、先が依存される側。`A ⇢ B` は「A が B を使う」。
B が変わると A が影響を受ける、と読む。

### 包含との違い

| | 包含（⊕） | 依存（破線矢印） |
| --- | --- | --- |
| 意味 | 持っている | 使っている |
| 持ち主が消えると | 中身も消える | 相手は残る |

## ビューとビューポイント {#pkg-view}
items: mu-view-viewpoint
term: ビューポイント | びゅーぽいんと | «viewpoint»。誰の（stakeholders）どんな関心（concerns）に、何の目的で応えるかを定めたもの
term: ビュー | びゅー | «view»。ビューポイントに従って、モデルから必要な部分を集めたもの

### 一文で

**ビューポイントは「誰に何を見せるか」の決まり、ビューはその決まりに従った見せ方**。

| | ビューポイント | ビュー |
| --- | --- | --- |
| ステレオタイプ | `«viewpoint»` | `«view»` |
| 持つもの | stakeholders / concerns / purpose / languages / methods | モデル要素（インポートで集める） |
| 例 | 安全担当者向け・安全上の懸念 | 安全ビュー |

### 関係

**ビューは `«conform»` でビューポイントに従う**（v1.2）。矢印はビューからビューポイントへ。

```
«view» SafetyView ⇢«conform»⇢ «viewpoint» SafetyViewpoint
```

ビューは特殊なパッケージなので、pkg に描く。

## モデルの階層を作る {#pkg-hierarchy}
items: mbf-hierarchy
term: モデルライブラリ | もでるらいぶらり | «modelLibrary»。複数のモデルで再利用する要素（値型・単位など）を入れるパッケージ

### 分け方の型

| 分け方 | 例 | 向いている所 |
| --- | --- | --- |
| 図の種類・観点で | Requirements / Structure / Behavior / Analysis | 小〜中規模。試験の問題はたいていこれ |
| システムの分解で | Vehicle / Powertrain / Chassis | 大規模・分担作業 |
| 再利用で | 値型・単位を `«modelLibrary»` に | 共通部品 |

### 判断の分かれ目

- **最上位は `«model»`**（モデル全体）。その下にパッケージ
- 共通の値型・単位は**モデルライブラリ**に分け、使う側から `«import»`
- 循環依存（A が B を、B が A をインポート）は避ける

## パッケージ図を作る {#pkg-build}
items: mbf-build-pkg

### 手順

1. **ヘッダ**: `pkg [model] 名前 [図の名前]` か `pkg [package] …`
2. パッケージをフォルダで置く。中に入れるか ⊕ の線で包含を示す
3. 使う関係を `«import»` などの依存で引く（**矢印は使う側から**）
4. ビューを描くなら `«view»` と `«viewpoint»` を `«conform»` でつなぐ

### 確かめる観点

| 観点 | 正しい形 |
| --- | --- |
| ⊕ の位置 | 持ち主の側 |
| 依存の向き | 使う側 → 使われる側 |
| 要素の持ち主 | 1 つだけ |
| ビュー | `«conform»` でビューポイントへ |
