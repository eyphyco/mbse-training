## シーケンス図は何を表す図か {#sd-purpose}
items: mu-sd-purpose
term: シーケンス図 | しーけんすず | sd。部品（ライフライン）どうしが交わすメッセージの順序を表す図
term: 相互作用 | そうごさよう | interaction。シーケンス図が表すもの。ヘッダの型は interaction

### 一文で

**sd は、特定の場面で、部品どうしがどの順にメッセージを交わすかを表す図**。時間は**上から下**へ流れる。

### いつ使うか

- 特定の**シナリオ**（ユースケースの 1 つの流れ）を詳しく描く
- インタフェース（どんな操作・シグナルが要るか）を洗い出す

### アクティビティ図との違い

| | act | sd |
| --- | --- | --- |
| 主役 | 処理と流れるもの | **誰が誰に**送るか |
| 時間 | 矢印の順 | **縦軸** |
| 向いている所 | 機能の分解 | シナリオ・インタフェース |

## ライフラインとメッセージ {#sd-lifeline}
items: mu-lifeline-message
figures: sd-start
term: ライフライン | らいふらいん | 相互作用に参加する部品。上の箱 `名前 : 型` と、下へ伸びる破線
term: 同期メッセージ | どうきめっせーじ | 送った側が返事を待つ呼び出し。実線 + 塗りつぶした矢じり
term: 非同期メッセージ | ひどうきめっせーじ | 送った側が待たないメッセージ。実線 + 開いた矢じり

### 記号

| 記号 | 名前 | 意味 |
| --- | --- | --- |
| 箱 + 下へ伸びる破線 | ライフライン | 参加する部品 `driver : Driver` |
| 実線 + **塗った**矢じり ▶ | **同期** | 呼んで、返事を待つ |
| 実線 + **開いた**矢じり > | **非同期** | 送って、待たない（シグナル） |
| **破線** + 開いた矢じり | 応答 | 同期呼び出しの返事 |
| ライフラインの上の細い長方形 | 実行仕様 | その間、処理している |
| × | 破棄 | ライフラインの終わり |

### ここが最重要: 矢じりの形

| | 同期 | 非同期 |
| --- | --- | --- |
| 矢じり | **塗りつぶし** | **開いた** |
| 送った側 | 返事が来るまで待つ | すぐ次へ進む |
| よくある使い方 | 操作の呼び出し | シグナル |

### 順序

**上にあるメッセージが先**。2 本のライフラインの間で、縦の位置が時間の順を表す。

## 相互作用参照と複合フラグメント {#sd-ref}
items: mu-interaction-ref
term: 相互作用参照 | そうごさようさんしょう | `ref` と書いた箱。別のシーケンス図（相互作用）をここで行う、という参照
term: 複合フラグメント | ふくごうふらぐめんと | `alt` `opt` `loop` `par` などを左上に書いた箱。メッセージの選択・繰り返し・並行を表す

### ref の箱

```
┌ref────────────────────────────┐
│        StartEngine            │
└───────────────────────────────┘
```

**`ref` の箱は、別の図（相互作用）をここに差し込む**、という意味。長い流れを分けて、同じ部分を使い回す。
箱がまたいでいるライフラインが、参照先の図に参加する。

### 複合フラグメント

| 札 | 意味 |
| --- | --- |
| `alt` | どれか 1 つ（破線で区切った区画ごとに `[ガード]`） |
| `opt` | 条件が真のときだけ |
| `loop` | 繰り返す |
| `par` | 区画が並行に起きる |
| `break` | 条件が真なら、残りをやめて抜ける |

### 取り違えやすい点

- `ref` は**呼び出し**ではなく、図の**差し込み**
- `alt` は複数の区画から 1 つ、`opt` は区画 1 つで「やるかやらないか」

## シーケンス図を作る {#sd-build}
items: mbf-build-sd

### 手順

1. **ヘッダ**: `sd [interaction] 名前 [図の名前]`
2. 参加する部品をライフラインで並べる（`名前 : 型`。型は bdd のブロック）
3. メッセージを**上から順に**引く。待つなら同期、待たないなら非同期
4. 分岐・繰り返しは複合フラグメント
5. 別の図で描いた部分は `ref` で参照

### 確かめる観点

| 観点 | 正しい形 |
| --- | --- |
| ヘッダの型 | `interaction` |
| ライフラインの型 | bdd のブロック |
| 返事を待つ呼び出し | 塗った矢じり + 応答は破線 |
| シグナル | 開いた矢じり |
| 繰り返し | `loop` |

## 振る舞いをモデルでどう捉えるか（第 7〜9 章のまとめ） {#beh-capture}
items: mbf-beh-capture

### 3 つの道具の使い分け

| 問い | 道具 | 図 |
| --- | --- | --- |
| 何をどの順で行い、何が流れるか | **アクティビティ** | act |
| イベントで**どの状態に変わるか** | **状態機械** | stm |
| 部品どうしが**どの順にやりとりするか** | **相互作用** | sd |
| 外から見た使われ方 | ユースケース | uc |

### 判断の分かれ目

- 入力を**変換して出力する**流れ（燃料 → トルク）→ アクティビティ
- **モード**があり、同じ入力でも状態で反応が変わる → 状態機械
- 特定の**シナリオ**での部品間のメッセージの順 → シーケンス図
