## 制約ブロック {#par-constraint-block}
items: mu-constraint-block
figures: bdd-valuetypes
term: 制約ブロック | せいやくぶろっく | «constraint»。式（制約）と、式に出る変数（パラメータ）をまとめた再利用できる部品
term: パラメータ | ぱらめーた | 制約ブロックの式に出る変数。parameters 区画に `名前 : 型` で書く
term: 制約プロパティ | せいやくぷろぱてぃ | 制約ブロックで型付けされたプロパティ。par では角の丸い箱で描く

### 一文で

**制約ブロックは、式を部品として定義したもの**。bdd に `«constraint»` の箱で描く。

```
«constraint»
NewtonsLaw
─────────────
constraints
{f = m * a}
─────────────
parameters
f : Force
m : Mass
a : Acceleration
```

| 区画 | 中身 |
| --- | --- |
| `constraints` | 式。`{ }` で囲む |
| `parameters` | 式に出る変数と、その型（値型） |

> 図の上の表記は `«constraint»`。モデルの要素名は ConstraintBlock。ヘッダの型には `constraintBlock` と書く。

### なぜ部品にするか

同じ式（ニュートンの法則）を、車にも台車にも使い回せる。**定義と使用**（第 1 章）が式にも効く。
ブロックが制約ブロックを持つときは、bdd で**黒ひし形**を引く（制約プロパティになる）。

## パラメトリック図は何を表す図か {#par-purpose}
items: mu-par-purpose
term: パラメトリック図 | ぱらめとりっくず | par。制約（式）のパラメータと、システムの値属性のつながりを表す図。工学解析のための図
term: 束縛コネクタ | そくばくこねくた | binding connector。par でパラメータと値属性（または別のパラメータ）をつなぐ実線。両端の値が等しいことを表す

### 一文で

**par は、式のパラメータをシステムの値属性に配線する図**。性能・質量・電力などの**工学解析**を、モデルとつないで行うためにある。

| 箱 | 意味 |
| --- | --- |
| 角の丸い箱 `newton : NewtonsLaw` | **制約プロパティ**（制約ブロックの使用） |
| 角丸の箱の縁の小さな四角 | パラメータ |
| 角の立った箱 `vehicle.mass` | 値属性 |
| 実線 | **束縛コネクタ**（等しい） |

### 利点

- 解析の式が、**どの値属性に効くか**がモデルの中で辿れる
- 設計を変えたとき、影響する式がすぐ分かる
- 解析ツールへ渡す元になる

### ここが最重要: 向きが無い

par の式は**代入ではなく等式**。`f = m * a` は、f から m を求めても、m と a から f を求めてもよい。
**矢印は描かない**。どれを入力にするかは解析のときに決める。

## 制約プロパティ・パラメータ・式 {#par-param}
items: mu-constraint-param

### 読み方

```
┌───────────────────────┐
│ newton : NewtonsLaw   │   ← 制約プロパティ（角丸）
│ {f = m * a}           │   ← 式を書き添えてもよい
□f        □m        □a   │   ← パラメータ（縁の四角）
└───────────────────────┘
```

| 見たもの | それは何か |
| --- | --- |
| `newton` | 制約プロパティの名前（使用） |
| `NewtonsLaw` | 制約ブロック（定義） |
| 縁の `f` `m` `a` | パラメータ。制約ブロックの parameters 区画と同じ名前 |

### 区別

| | 制約ブロック | 制約プロパティ |
| --- | --- | --- |
| 図 | bdd | par |
| 箱 | 角の立った箱 `«constraint»` | **角の丸い**箱 |
| 名前 | `NewtonsLaw` | `newton : NewtonsLaw` |

## 束縛コネクタ {#par-binding}
items: mu-binding

### 意味

**束縛コネクタは「両端の値が等しい」**を表す実線。矢印は無い。

```
[vehicle.mass] ──── □m  newton : NewtonsLaw
```

「`vehicle.mass` の値と、式の `m` の値は等しい」と読む。

### 規則

- つなぐのは**パラメータと値属性**、または**パラメータとパラメータ**
- 両端の**型（単位）が合っている**こと（Mass と Mass）
- 値属性は `vehicle.mass` のように**ドット記法**で、囲みブロックからの道筋を書く

### ibd のコネクタとの違い

| | ibd のコネクタ | 束縛コネクタ |
| --- | --- | --- |
| 意味 | つながっている（流れうる） | **値が等しい** |
| つなぐもの | パート・ポート | パラメータ・値属性 |

## 解析を制約でどう捉えるか {#par-capture}
items: mbf-par-capture

### 捉え方

| 問い | 道具 |
| --- | --- |
| どんな式が要るか | 制約ブロック（bdd で定義） |
| どのブロックの解析か | 囲みブロック（par のヘッダ） |
| 式の変数はどの値か | 束縛コネクタで値属性へ |
| 式どうしの受け渡し | パラメータどうしを束縛 |

### 判断の分かれ目

- 式を 1 つの大きな制約ブロックにせず、**意味のある単位に分けて**つなぐ（再利用できる）
- 値属性の型は**単位を持つ値型**にしておく。束縛の両端で単位が合うかを確かめられる
- 「解析ケース」（どの条件で解くか）は、囲みブロックを解析用に作って分けることが多い

## 制約を bdd に定義する {#par-define}
items: mbf-define-constraint

### 手順

1. bdd に `«constraint»` の箱を置き、`constraints` 区画に式を `{ }` で書く
2. `parameters` 区画に、式に出る変数を `名前 : 値型` で並べる
3. 制約を使うブロックから、制約ブロックへ**黒ひし形**を引く（ロール名が制約プロパティの名前になる）

### 確かめる観点

| 観点 | 正しい形 |
| --- | --- |
| 式 | `{ }` で囲む |
| パラメータ | 式に出る変数がすべてある |
| パラメータの型 | 値型 |
| 使う側との関係 | コンポジション |

## par を作る {#par-build}
items: mbf-build-par

### 手順

1. **ヘッダ**: `par [block] 解析対象 [図の名前]`（制約ブロックの中を描くなら `[constraintBlock]`）
2. 制約プロパティを**角丸の箱**で置く。縁にパラメータ
3. 値属性を角の立った箱で置く（`vehicle.mass`）
4. **束縛コネクタ**で、パラメータと値属性をつなぐ
5. 式どうしで値を受け渡すなら、パラメータどうしをつなぐ

### 確かめる観点

| 観点 | 正しい形 |
| --- | --- |
| 線 | 実線、**矢印なし** |
| 制約プロパティ | 角丸。`名前 : 制約ブロック` |
| 両端の型 | 単位が合う |
| 図枠の縁の四角 | 囲みが制約ブロックのとき、そのパラメータ |
